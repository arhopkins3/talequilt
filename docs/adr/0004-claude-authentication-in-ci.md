# 0004. Claude authentication in CI: Console API key with a spend limit

- **Status:** Accepted
- **Date:** 2026-10-09
- **Deciders:** Alex Hopkins
- **Phase:** 0 (used from Phase 4)

## Context

The Claude Code GitHub Action must authenticate to the Claude API. It accepts an Anthropic Console API key, a Claude Pro or Max subscription token generated by `claude setup-token`, or Workload Identity Federation, where the workflow exchanges its GitHub OpenID Connect token for a short-lived Anthropic token and stores no secret.

## Options considered

| Option | For | Against | Monthly cost |
| --- | --- | --- | --- |
| Console API key, repository secret, monthly spend limit | Spend separate from personal use, auditable in the Console, does not expire with a login | A long-lived secret to protect and rotate | Usage-based; expect single-digit pounds per month in Phase 4, capped in the Console |
| Subscription token | Covered by an existing subscription | Shares personal rate limits; ties the pipeline to one person's account; tokens expire | £0 marginal |
| Workload Identity Federation | No stored secret; best corporate story | Needs Console organisation admin and more setup | Usage-based |

## Decision

A Console API key stored as a GitHub Actions secret, with a monthly spend limit set in the Console. Federation is revisited as a Phase 4 lesson once the agent workflows exist.

## Consequences

The key is rotated if it ever appears in a log. Workflows that use it declare minimal permissions and a turn limit. Model spend per merged pull request is a Phase 4 metric.

## At company scale

Companies route model calls through their own cloud account or an enterprise gateway for data retention terms, use federation or short-lived credentials instead of static keys, and allocate budgets per team.
